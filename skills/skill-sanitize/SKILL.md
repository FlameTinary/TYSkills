# 技能脱敏

把一个技能里**属于某台机器、属于作者本人**的内容清干净：审计 → 分类处置（删除 / 参数化 / 占位 /
保留并写理由）→ 需要私有化的值改成用户自己的配置文件。产物是「换一台机器、换一个人，照样能用」的技能目录。

本技能只做脱敏。跨平台适配、给其他 agent 打包安装、发布到仓库，都不在它的职责内。

## When to Use

- 要把一个原本本机自用的技能交给别人 / 上传到公开仓库 / 发给同事
- 用户说「脱敏」「去掉本机信息」「去掉我机器上的东西」「让任何人都能用」
- 复查一个已经公开的技能里是否还残留本机内容

Don't use for: 只在本机自用的技能（没有别人看，不必付出脱敏成本）；从零写新技能
（用 `hermes-agent-skill-authoring`）；把一个干净目录发布出去（那是另一个流程，不归这里）。

## 判定口径

**这条信息在别人的机器上是否同样成立？** 成立 → 公共知识，保留；不成立 → 本机内容，处置。

判据不是「值看起来随机」，而是「它能不能在你机器之外指认某个人，或换到某个权限」。

## 红线（不可协商）

1. **不做「看起来脱敏」**：凡是能唯一指认某个人或某台机器的字符串，一律处置 —— 用户名、主机名、
   家目录、外接盘卷标、局域网 IP、私有域名、个人服务名、邮箱、机器状态叙述。
2. **秘密是删除 + 轮换，不是脱敏**：凭据一旦进过公开仓库就视为已泄漏；改文件不算修复，
   必须去源头轮换（吊销 token、改密码、重签密钥）。
3. **要私有化的走配置文件**，不写死、不猜默认：没有配置时给出可读报错或安全降级，
   绝不静默使用某个「作者机器上成立」的值。
4. **审计脚本要跑，不靠眼睛**：`scripts/audit_skill.py` 退出码非零，就是还没脱敏完。

## 分类处置表

| 类别 | 典型内容 | 处置 |
|---|---|---|
| 秘密 | token、password、私钥、refresh_token、Cookie、Authorization 值、含密码的 URL | 删；改环境变量或配置文件；提醒轮换 |
| 身份 | 家目录路径、用户名、主机名、卷标（/Volumes/X）、邮箱、局域网 IP | 改 `~` / `expanduser` / `%USERPROFILE%` / 占位符 |
| 私有设施 | 私有域名、个人服务名、本机代理端口、NAS/设备品牌、私有站点名 | 改通用占位；需要保留则做成配置项 |
| 通用但被写死 | 端口号、盘符、包管理器命令 | 保留（属公共知识），但确认是软件默认值而不是改过的 |
| 个人叙述 | 以个人环境为依据的叙述（自有设备、所属网络、公司/项目名） | 改中性表述；经验值可以留，去掉指认性 |

## 私有配置模式

要私有化的东西（路径、端口、密钥、站点命令、盘位）一律进配置文件，不留在代码里。

- 位置：`~/.<技能名>/<技能名>.conf`（Windows 为 `%USERPROFILE%\.<技能名>\<技能名>.conf`），
  只提交 `assets/<技能名>.conf.template`，真实 conf 写进 `.gitignore`。
- 优先级：**命令行参数 > 环境变量 > 配置文件 > 内置默认**。
- 读取：用 `assets/conf_loader.py`（仅标准库，直接抄进被脱敏的技能），支持 `~` 与 `${VAR:-默认}` 展开。
- 生成：安装脚本首次运行时从模板生成，并随机化 secret；POSIX 下 `chmod 600`。
- 报错：缺配置时报「缺什么、去哪配、模板在哪」，**不回显密钥**。

模板见 `assets/private.conf.template`，模板里的键名就是给用户填的契约。

## 流程

1. **冻结现状**。确认技能目录可写、改动可追溯（是 git 仓库就先提交，或先 `cp -R` 备份一份）。
   完成判据：`git status --short` 为空，或只有你有意保留的改动。
2. **跑审计**。`terminal(command="python3 <技能目录>/scripts/audit_skill.py <技能目录> --report 报告.md")`。
   完成判据：拿到分级清单 + 报告文件，`high` 全部在明处。
   把自己机器专属的词补进去：`--terms ~/.config/skill-sanitize/local-terms.txt`，一行一词
   （用户名、主机名、域名、站点名、盘标、设备名）—— 通用规则抓不到的靠词表兜底。
3. **分类处置**。逐条 high/medium 决定：删除 / 参数化 / 占位 / 保留并写理由。同一根因只决定一次，
   但要替换**所有**出现处（用 `--json` 聚合，别按文本输出的前几条手改）。
   完成判据：报告里每条都有处置结论。
4. **落地配置**。凡是「作者机器上的值」都迁到 conf 模板 + loader，脚本改成读配置。
   完成判据：没有配置文件时脚本给出可读报错且不崩；复制模板填好即可跑通。
5. **复检并留档**。重跑审计 + 手工确认，把处置结论整理进报告归档。
   完成判据：`--fail-level high` 退出码 0；「保留」项都写了理由；报告存放在本地
   （含命中原文，不要提交到公开仓库）。

## 「保留」要留痕：audit-skip 豁免

审计器会命中文档里**必须保留的反面示例**（`example` 占位、示例令牌、规则定义本身）。这类内容
不要为了通过审计而删改，而是就地记账：

```markdown
<!-- audit-skip-file: 本文档是反面示例库，表内字面量是教学用的错误写法 -->   # 文件级（前 8 行内）
… `rpc-secret=abcd1234` …            <!-- audit-skip: 报告模板里的虚构示例值 -->   # 行级
```

- 两种标记都必须写理由；理由会出现在文本输出、`--json` 的 `exemptions` 和报告里，可追溯、可复核。
- 豁免**不是静默跳过**：它只是把「保留」这个决定显式化，真实值仍然要处置。

## Quick Reference

```bash
# 审计（退出码 0 = 达到 --fail-level 的问题数为 0）
python3 scripts/audit_skill.py <技能目录> [<技能目录2> ...] \
        [--json] [--terms 词表文件] [--report 报告.md] [--fail-level high] [-q]
```

## Pitfalls

1. **只改 SKILL.md**。同一个路径值在 `scripts/`、`references/`、`assets/` 里通常还有 4~5 份，
   漏一个等于没做。用 `--json` 按规则聚合后全量替换。
2. **把示例改成另一个本机值**（比原样更糟）。示例一律用 `example.com` / `example.invalid` /
   `<占位>` / `com.example.<服务>`。
3. **过度脱敏**。把软件默认端口、公知上游 URL、标准路径也删掉 → 文档失去可操作性。
   默认值是公共知识，保留。
4. **忘了文件之外的面**。git 提交者姓名/邮箱、旧提交里的密钥、`.git/logs`、截图里的书签栏、
   终端输出样本里的家目录提示符，都是泄漏面。已推送过的秘密必须轮换，不能只改文件。
5. **折叠计数**：审计输出对同一规则有折叠上限，看 `--json` 的汇总数字，别以为前 5 条就是全部。
6. **改写把文件改坏**：frontmatter 起止被破坏、BOM/CRLF、编码变化。审计器会一起报，
   别只顾着替换字符串。

## Verification

- [ ] `python3 scripts/audit_skill.py <技能目录>` 退出码 0（`high` 为 0），或每条 high 都有书面理由
- [ ] 全目录搜不到：用户名、主机名、家目录、卷标、私有域名、局域网 IP、令牌/密码/邮箱
- [ ] 无配置文件时脚本给出可读报错；复制 `*.conf.template` 填好后可跑通
- [ ] 脱敏改写后文件结构完好：frontmatter 起止正常、无 BOM、行尾一致
- [ ] 报告归档在本地，每条处置（含「保留」）都有理由
