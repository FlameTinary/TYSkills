# 目录结构规范

> 核心原则：PARA 按【行动状态】分类，不按文件类型分类。
> 文件夹是物理位置（一篇笔记只能在一处），链接 / MOC 是逻辑关系。

## 目录

1. 顶层结构
2. 各 PARA 目录定义与示例
3. 辅助目录

## 1. 顶层结构

```
你的笔记库/
├── 01-Projects/          # 项目：有目标+截止时间，做完即归档
├── 02-Areas/             # 领域：长期负责、无截止日期、持续维护
├── 03-Resources/         # 资源：未来可能用到的素材/参考
├── 04-Archives/          # 归档：已结束、不再主动维护
├── Templates/            # 模板：笔记模板存放处
├── MOC/                  # 内容地图：各分区的索引页
├── Assets/               # 附件：图片、PDF、嵌入文件
└── 99-Inbox/             # 收件箱：未处理的闪念/采集（强烈建议）
```

编号前缀让文件夹在 Obsidian 侧栏固定排序，PARA 顺序就是行动优先级——先看 Projects，再看 Areas。

## 2. 各 PARA 目录定义与示例

### 01-Projects/（项目）

定义：有明确目标 + 截止时间，完成后转入 Archives。一篇笔记 = 一个项目。

```
01-Projects/
├── 搭建Obsidian第二大脑/
│   ├── 项目主页.md
│   ├── 调研资料.md
│   └── 执行日志.md
├── 撰写Q3工作总结.md
└── 准备XX会议汇报.md
```

- 存放：正在推进的具体事项——写论文、剪视频、做汇报、搬家、备考。
- 规则：
  - 项目少时直接在 `01-Projects/` 下放单篇笔记。
  - 项目超过 5 篇关联笔记时，才建同名文件夹。
  - 最多 2 级：`01-Projects/项目名/笔记.md`，不再嵌套。

### 02-Areas/（领域）

定义：长期持续负责、没有截止日期、需要定期维护的责任范围。

```
02-Areas/
├── 01-健康管理.md
├── 02-职业发展.md
├── 03-财务投资.md
├── 04-家庭人际.md
├── 05-个人成长.md
└── 06-内容创作.md
```

- 存放：长期在意并需持续投入的方向——健康、职业、理财、婚姻、育儿、副业。
- 规则：
  - 每个领域就是一篇 MOC 笔记，不建子文件夹。
  - 领域之间用 `[[]]` 互链，不用文件夹嵌套。
  - 新建领域前自问："这件事我需要长期负责吗？" 一次性的事是 Project 不是 Area。

### 03-Resources/（资源）

定义：感兴趣、未来可能用到，但没有必须完成的任务。素材仓库。

```
03-Resources/
├── 01-文章素材/
├── 02-书籍摘录/
├── 03-教程课程/
├── 04-工具软件/
├── 05-灵感金句/
└── 06-剪贴收藏/
```

- 存放：好文章、书摘、课程笔记、工具评测、代码片段、金句。
- 规则：
  - 子文件夹按素材来源 / 主题粗分，不过度细分。
  - 不确定放哪个子文件夹时，直接放 `06-剪贴收藏/`。
  - 优先靠标签和 MOC 关联，而不是新建子文件夹。

### 04-Archives/（归档）

定义：已经结束、不再主动维护的内容。放着备查，不主动打开。

```
04-Archives/
├── 01-已完成项目/
├── 02-已结束领域/
└── 03-旧资源/
```

- 存放：做完的项目、放弃的领域、过期参考资料。
- 规则：
  - 归档 = 改 frontmatter 的 status + 物理移动，两步缺一不可。
  - 归档后不再加新内容；需复活时改回 status 并移回原目录。

## 3. 辅助目录

| 目录 | 作用 | 规则 |
|---|---|---|
| `Templates/` | 存放 4 套笔记模板 | Obsidian 设置 → 核心插件 → 模板 中指定此路径 |
| `MOC/` | 内容地图索引页 | 每个 PARA 分区 + 每个 Area 对应一篇 MOC |
| `Assets/` | 所有附件（图片/PDF） | 设置 → 文件与链接 → 附件默认路径设为此目录 |
| `99-Inbox/` | 闪念、未分类采集 | 每周复盘清空，清空后可以为空 |

## 4. 何时新建 / 不新建文件夹

| 情况 | 做法 |
|---|---|
| 同一主题下已有 >5 篇笔记且会持续增加 | 建子文件夹 |
| 只是一两篇相关笔记 | 不建，用 `[[]]` 链接到对应 MOC |
| 不确定这个主题以后还会不会用 | 不建，先放 `99-Inbox/` 或 `03-Resources/06-剪贴收藏/` |
| 想按"标签"分类 | 不建，用标签 |
| 一个领域下有多个项目 | 领域保持单篇 MOC，项目各自在 `01-Projects/`，用 frontmatter 的 area 字段关联 |

铁律：文件夹是物理仓库，MOC 是逻辑地图。想用文件夹做"分类"时，先用 MOC + 标签 + Dataview 解决，解决不了再建文件夹。
