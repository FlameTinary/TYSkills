# 命名规范与标签体系

## 目录

1. 文件命名规则
2. 标签策略（推荐 / 禁用）
3. 链接 / 标签 / Dataview / frontmatter 的选择

---

## 1. 文件命名规则

### 通用规则

- 禁止特殊字符：`/ \ : * ? " < > | # ^ [ ]`（Obsidian 会出问题）
- 不用日期做文件名前缀（日期放 frontmatter 的 created 字段）
- 用名词短语，简洁见名知意：`Obsidian双链用法`，而非 `今天学了Obsidian的双链功能总结一下`
- 同一概念全库统一叫法（统一叫"双链"，不要一篇"双向链接"一篇"backlink"）

### 各类型笔记命名

| 类型 | 命名格式 | 示例 |
|---|---|---|
| Project 项目 | 动宾短语，直接写 | `搭建个人知识库`、`Q3工作总结` |
| Area 领域 | 名词短语 | `健康管理`、`职业发展` |
| Resource 资源 | 文章/书籍/视频标题原文 | `深度工作`、`为什么专注力是稀缺资源` |
| Archive 归档 | 保持原名，不改 | （从 Projects 移过来时名字不变） |
| MOC 地图 | 统一前缀 `MOC-` | `MOC-职业发展`、`MOC-Projects总览` |
| 日记/日志 | `YYYY-MM-DD` | `2026-09-28` |

## 2. 标签策略

核心原则：PARA 不靠标签做分类，文件夹已经分类了。标签只做**属性标记**——标记跨文件夹、跨领域的元信息。总数控制在 20 个以内。

### 推荐标签清单

| 标签 | 用途 | 示例场景 |
|---|---|---|
| `#inbox` | 未处理的收件箱笔记 | 刚采集还没整理 |
| `#source/book` | 来源是书 | 书摘笔记 |
| `#source/article` | 来源是文章 | 网页剪藏 |
| `#source/video` | 来源是视频 | 视频逐字稿 |
| `#source/podcast` | 来源是播客 | 播客笔记 |
| `#source/personal` | 自己原创的 | 自己写的稿子 |
| `#status/waiting` | 等待外部反馈 | 等别人回复、等审批 |
| `#status/blocked` | 卡住了 | 缺资料、缺权限 |
| `#priority/high` | 高优先级 | 本周必须推进 |
| `#review/weekly` | 需要每周回顾 | 健康数据、读书进度 |
| `#review/monthly` | 需要每月回顾 | 财务复盘 |

### 绝对不要用的标签

| 禁止标签 | 原因 | 替代方案 |
|---|---|---|
| `#project` `#area` `#resource` | 文件夹已区分，重复 | frontmatter 的 type 字段 |
| `#工作` `#生活` `#学习` | 这是分类不是属性，会膨胀 | 建 Area 文件夹 / MOC |
| `#2026` `#九月` | 时间维度用 Dataview 按日期查 | frontmatter 的 created 字段 |
| `#重要` `#待整理` | 太模糊，没有边界 | `#priority/high` 和 `#inbox` |
| 自创两级以上嵌套标签 | 标签树会失控 | 标签最多两级：`#source/book` |

## 3. 链接 / 标签 / Dataview / frontmatter 的选择

| 场景 | 用什么 | 举例 |
|---|---|---|
| 两篇笔记有直接引用 / 支撑关系 | `[[]]` 内链 | 项目主页 `[[健康管理]]` 链接到领域 MOC |
| 笔记有跨文件夹的共性属性 | `#标签` | 所有书摘打 `#source/book` |
| 需要动态列表（自动汇总） | Dataview 查询 | 自动列出所有进行中的项目 |
| 建立"属于哪个领域"的关系 | frontmatter 的 `area` 字段 | `area: "[[职业发展]]"` |
| 手动维护一组索引 | MOC 笔记 | 手写 `MOC-职业发展` 里的链接列表 |

判断口诀：

- 有关系就链接（这篇提到了那篇）
- 有属性就打标签（书摘 / 等待 / 高优）
- 要汇总就 Dataview（手动列太累）
- 拿不准就先放 Inbox，周复盘再决定
