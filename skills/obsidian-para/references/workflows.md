## 1. 新建笔记判断流程

拿到一个想法 / 素材，按此顺序判断：

```
这条笔记有截止日期吗？
├── 有 → 有明确要达成的目标吗？
│   ├── 有 → 【Project】放到 01-Projects/
│   └── 没有（只是个待办事项）→ 拆成任务，归到对应 Area 的任务清单
└── 没有 → 我需要长期对这件事负责吗？
    ├── 是（健康、职业、家庭…）→ 【Area】在 02-Areas/ 建/补领域 MOC
    └── 否 → 对我有用、未来可能用到吗？
        ├── 是 → 【Resource】放到 03-Resources/ 对应子文件夹
        └── 暂时不确定 → 【Inbox】扔 99-Inbox/，周复盘再决定
```

30 秒判断口诀：

- 有 deadline = Project
- 长期要操心 = Area
- 只是觉得有用 = Resource
- 拿不准 = Inbox

## 2. 旧知识库迁移步骤

**第 1 步：建空壳**
- 按目录规范建好完整结构（空文件夹即可）
- 把 4 套模板放进 `Templates/`
- 建好 `MOC/MOC-Home.md`

**第 2 步：清空 Inbox**
- 所有旧笔记先移到 `99-Inbox/`，不要一开始就分类（摆脱完美分类强迫症）

**第 3 步：批量过一遍（每次 20-30 分钟）**
- 打开 Inbox，逐篇判断 P / A / R / 拿不准
- 拿不准的先留 Inbox，不纠结
- 每篇移动后顺手补 frontmatter 的 `type` 字段（其他字段后补）

**第 4 步：清理冗余**
- 完全没用的笔记（过期通知、临时草稿）直接删
- 重复笔记合并
- 只有标题没有内容的空笔记，补内容或删

**第 5 步：建 MOC**
- Inbox 清空后打开 `MOC/MOC-Home.md`
- 让 Dataview 自动列出项目和领域
- 手动补 2-3 个最重要的 Area MOC

迁移原则：不追求一次到位。先用 80% 的笔记完成 80% 的归类，剩下 20% 在使用中自然归位。

## 3. 每周 / 每月复盘清单

### 每周日晚 20 分钟

- [ ] 清空 `99-Inbox/`：每篇归类到 P/A/R 或删除
- [ ] 过 `01-Projects/`：哪些状态变了（active → on-hold → done）
- [ ] 检查本周到期项目：延期还是放弃
- [ ] 扫最近新增 Resource：有没有能链接到现有项目 / 领域的

### 每月最后一天 30 分钟

- [ ] 过所有 Active Area：这个月在该领域做了什么
- [ ] 有没有该归档的项目（status = done）
- [ ] 长期没动的 Resource（超 3 个月）考虑归档或删除
- [ ] 更新 `modified` 字段
- [ ] 检查标签：重复 / 同义标签合并

## 4. 项目完成后的归档流程

1. **改 frontmatter**：`status: active → done`，在「执行日志」补完成总结
2. **物理移动**：把项目文件夹 / 笔记从 `01-Projects/` 拖到 `04-Archives/01-已完成项目/`
3. **补归档字段**：`archived-date`、`archive-reason`
4. **更新 MOC**：对应 Area MOC 的「进行中项目」Dataview 自动消失；在 Area MOC 末尾「历史项目」手动加链接
5. **检查双向链接**：打开归档笔记的反向链接面板，确认没有 active 笔记仍在引用它

## 5. 边界案例判断

| 案例 | 归类 | 理由 |
|---|---|---|
| 一本书的读书笔记 | **Resource** | 是素材，不是要"完成"的事 |
| 正在读的一本书（有读完期限） | **Project** | 如"10 月前读完《深度工作》并写读后感" |
| 学一门课程（有作业、有截止） | **Project** | 有明确目标和完成标准 |
| 收藏的一堆课程视频（只是存着） | **Resource** | 没有 deadline，只是素材 |
| 健身（长期坚持） | **Area** | 没有终点，持续维护 |
| 备考 CFA 三级 | **Project** | 有考试日期，考完即结束 |
| 健康饮食这个习惯 | **Area** | 长期责任 |
| 一篇要发布的文章草稿 | **Project** | 有发布目标，发布后归档 |
| 随便写的感悟日记 | **Resource** 或直接日记 | 个人记录，不需要 PARA 管 |
| 一个想放弃的副业方向 | 先 **Area**（active 观察），确认不做再归档 | 归档后复活成本高 |

## 6. 避坑指南

1. **不要用文件夹替代 MOC**：文件夹是仓库，MOC 是目录。文件夹越用越多 = 在和 MOC 抢工作。
2. **不要同时用两套分类体系**：PARA 文件夹管行动状态，标签只管属性（来源/状态/优先级）。两套并行决策成本翻倍。
3. **区分临时项目和长期领域**：
   - "这件事有做完的那天吗？" → 有 = Project
   - "这件事我需要一直操心吗？" → 是 = Area
4. **搁置 ≠ 放弃**：
   - 暂时搁置 1-2 周：不移动，`status: on-hold`
   - 资源暂时用不上：留在 Resources，用 Dataview 过滤
   - 领域半年没维护：不移动，`status: dormant`，月复盘决定
   - 彻底不做了：才移动到 Archives，`status: archived`
5. **其他**：
   - 不过度嵌套文件夹（最多 2 级）
   - 不给每篇笔记都打标签（标签是少数跨切面属性）
   - 不追求完美分类才开始写（先扔 Inbox）
   - 不装一堆插件（Dataview + Templater 可选 + Web Clipper 足够）
   - 不让 frontmatter 字段膨胀（加字段前问"会被 Dataview 用到吗"）
